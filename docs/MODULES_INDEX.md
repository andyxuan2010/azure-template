Notes:
- The module source path used throughout this repository is `./modules/<name>` when calling modules from the repo root.
- Root-wired modules have a matching root module block, `features` flag, `module_plan_enabled` toggle, root input variables, and `terraform.tfvars` sample values.
- `availabilityset`, `containerapp`, `fortigate`, `loadbalancer`, and `private_endpoint` are root-wired and participate in the CI module matrix.
- `acr`, `adf`, `aks`, `applicationgateway`, `appregistration`, `appservice`, `appserviceplan`, `automationaccount`, `availabilityset`, `azure_ai_service`, `azure_ai_search`, `containerapp`, `cosmosdb`, `databricks`, `enterpriseapplication`, `eventhub`, `firewall`, `fortigate`, `functionapp`, `keyvault`, `linuxvm`, `loadbalancer`, `loganalytics`, `logicapp`, `managedidentity`, `managementgroups`, `nsg`, `openai`, `policy`, `private_dns`, `private_endpoint`, `rg`, and `roleassignments` use the normalized documentation and test naming standard in [documentation.md](./documentation.md). Other modules retain legacy names until migrated.
- Some modules ship additional deep-dive docs beside the primary assets linked above.
- Default CI validates modules through the root harness. Review every module test to determine whether it uses mocked or real providers and whether it can create resources.
