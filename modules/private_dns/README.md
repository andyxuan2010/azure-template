# Azure Private DNS

Creates Azure Private DNS zones, virtual network links, optional SOA settings, and A, AAAA, CNAME, and TXT records.

## Features

- Multiple zones from one stable map input
- Multiple VNet links and record sets per zone
- Optional virtual network auto-registration
- Optional custom SOA record settings
- Resource-level tag overrides over the module tag baseline
- Optional resource group tag inheritance

## Resources Created

- Private DNS zones
- Private DNS zone virtual network links
- A, AAAA, CNAME, and TXT record sets

The module does not create virtual networks, private endpoints, Private Resolver resources, forwarding rulesets, or public DNS zones.

## Prerequisites and Dependencies

- An existing resource group for the zones
- Existing virtual network IDs for any VNet links
- A single authoritative Terraform owner for every zone, link, and record
- A DNS design covering hub/spoke links, auto-registration, hybrid resolution, and private endpoint zones

## Basic Usage

```hcl
module "private_dns" {
  source = "./modules/private_dns"

  resource_group_name         = "rg-platform-dns"
  inherit_resource_group_tags = false

  zones = {
    "privatelink.vaultcore.azure.net" = {
      a_records = {
        vault = {
          ttl     = 300
          records = ["10.20.1.10"]
        }
      }
    }
  }

  tags = {
    Environment = "prod"
    ManagedBy   = "Terraform"
  }
}
```

See [examples/basic](./examples/basic), [examples/complete](./examples/complete), and [examples/record-sets](./examples/record-sets).

## Zone and Link Ownership

Create each zone once and link it to every VNet that must resolve it. A VNet can have only one registration-enabled link for a given namespace, and private endpoint zones normally use `registration_enabled = false`.

Stable map keys form Terraform resource addresses. Renaming a zone, link, or record key can cause replacement even when other values remain unchanged.

## Records and Private Endpoints

Private Endpoint DNS zone groups normally manage endpoint A records. Avoid declaring the same record explicitly in this module unless record ownership is intentionally centralized and the private endpoint will not manage it.

## Tags

When inheritance is enabled and `inherited_resource_group_tags` is null, the module reads the resource group during planning. Prefer passing plan-known inherited tags from the root composition. Module `tags` override inherited values, and record or link tags override the module baseline.

## Testing

```powershell
terraform init -backend=false
terraform test -filter=tests/unit.tftest.hcl
```

Tests use a mocked AzureRM provider and do not create DNS resources.

## Known Limitations

- Only A, AAAA, CNAME, and TXT record resources are supported.
- Private DNS Resolver, forwarding rulesets, and hybrid DNS appliances are outside the module.
- The module does not discover or adopt existing zones, links, or records.
- Azure validates zone conflicts and VNet link constraints at apply time.

See [Architecture](./docs/architecture.md) for zone placement and resolution boundaries.
