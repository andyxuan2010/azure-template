# Azure Route Table

Creates an Azure route table with user-defined routes, optional Border Gateway Protocol (BGP) propagation control, subnet associations, deterministic naming, and resource-group tag inheritance.

## Features

- Declares multiple routes from a map with stable Terraform addresses.
- Associates one route table with multiple existing subnets.
- Supports `VirtualAppliance`, `VirtualNetworkGateway`, `VnetLocal`, `Internet`, and `None` next hops.
- Validates that a next-hop IP is used only for `VirtualAppliance`.
- Supports generated or explicit names and caller-overridden inherited tags.

## Resources Created

The module always creates one `azurerm_route_table`. It creates one `azurerm_subnet_route_table_association` for each value in `subnet_ids`.

The module does not create virtual networks, subnets, firewalls, network virtual appliances, route servers, gateways, or diagnostic settings.

## Prerequisites and Dependencies

- Existing resource group in the selected region
- Existing subnets for every requested association
- A reachable next-hop appliance IP when `next_hop_type = "VirtualAppliance"`
- Exclusive Terraform ownership of each subnet-to-route-table association
- A reviewed routing design that accounts for Azure system routes, BGP routes, and asymmetric traffic

## Provider Configuration

The caller supplies the default `azurerm` provider. The execution identity needs permission to create route tables and update every target subnet association.

## Basic Usage

```hcl
module "route_table" {
  source = "./modules/route_table"

  name                = "rt-application-cc-dev-001"
  resource_group_name = "rg-network-dev"
  location            = "canadacentral"

  routes = {
    internet = {
      address_prefix = "0.0.0.0/0"
      next_hop_type  = "Internet"
    }
  }

  subnet_ids = [module.vnet.subnet_ids["application"]]
}
```

See [examples/basic](./examples/basic), [examples/complete](./examples/complete), and [examples/firewall-egress](./examples/firewall-egress).

## Important Behavior and Secure Defaults

Route changes can immediately alter connectivity for every associated subnet. Review default routes, management paths, private endpoint traffic, and return paths before apply.

BGP propagation is enabled by default. Set `disable_bgp_route_propagation = true` only when the routing design intentionally suppresses learned routes. Caller tags override inherited resource-group tags.

## Networking

Each subnet can have only one effective route-table association. Import an existing association before asking this module to own it, and do not manage the same association from a VNet module or another state.

For a firewall or network virtual appliance, use the appliance's reachable private frontend IP and confirm that IP forwarding, health, routing, and policy are configured on the appliance. A route table alone does not provide inspection or network address translation.

## Identity and RBAC

The module creates no managed identities or role assignments. Grant the Terraform execution identity least-privilege access to the route table resource group and associated subnets.

## Naming and Tagging

Set `name` explicitly or allow `rt-<workload>-<location-code>-<environment>-<instance>` generation. See the repository [naming convention](../../docs/NAMING_CONVENTION.md) and [tagging standard](../../docs/TAGGING_STANDARD.md).

## Testing

```powershell
terraform init -backend=false
terraform test -filter=tests/unit.tftest.hcl
```

The unit suite mocks AzureRM and runs plan-only assertions. It requires no Azure authentication and creates no resources.

## Known Limitations

- Azure determines route precedence; the module does not calculate effective routes.
- The module does not validate reachability or health of a virtual appliance.
- Route-table flow logs and monitoring are outside this module.
- Changing the association set can affect live subnet traffic during apply.
- Azure Policy or another state can create association drift.

See [Architecture](./docs/architecture.md).
