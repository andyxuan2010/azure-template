# Azure Recovery Services vault

Creates an Azure Recovery Services vault that stores recovery points for Azure Backup workloads. The module configures the vault's SKU, backup storage redundancy, cross-region restore, public network access, immutability, generated name, and tags.

## Features

- Creates one Recovery Services vault in an existing resource group.
- Supports geo-redundant, locally redundant, and zone-redundant vault storage.
- Supports cross-region restore when using geo-redundant storage.
- Configures public network access and vault immutability.
- Generates a repository-style vault name when `name` is omitted and supports resource-group tag inheritance.

## Resources Created

The module creates one `azurerm_recovery_services_vault`. It does not create a resource group, backup policies, protected items, private endpoints, diagnostics, or role assignments.

## Prerequisites and Dependencies

- Existing resource group and Azure region
- The vault must be in the same region as the data sources it protects
- Cross-region restore requires `GeoRedundant` storage and has additional cost
- Set up workload-specific backup policies and protected items separately
- Configure supported private endpoints and DNS before disabling public network access

## Provider Configuration

The caller supplies the default `azurerm` provider. The execution identity needs permission to create and configure Recovery Services vaults in the target resource group.

## Basic Usage

```hcl
module "recovery_services_vault" {
  source = "./modules/recovery_services_vault"

  name                = "rsv-platform-cc-prod-001"
  resource_group_name = "rg-backup-prod"
  location            = "canadacentral"

  storage_mode_type = "ZoneRedundant"
  immutability      = "Unlocked"
  workload          = "platform"
  app_env           = "prod"

  tags = { Owner = "CCOE" }
}
```

See [examples/basic](./examples/basic) and [examples/complete](./examples/complete).

## Important Behavior and Secure Defaults

- The module defaults to `GeoRedundant` storage, matching the provider default and supporting regional recovery options. Choose the redundancy mode before starting backup protection; Azure restricts redundancy changes after recovery points exist.
- `cross_region_restore_enabled` is off by default. It requires geo-redundant storage, has added charges, and cannot be disabled after protection starts without replacing the vault.
- Immutability defaults to `Unlocked`, which can protect recovery points while allowing the setting to be reviewed before it is locked. Setting `immutability = "Locked"` is irreversible; review retention requirements and operational deletion/reconfiguration procedures first.
- Public network access defaults to enabled for compatibility with supported Azure Backup workloads. Disable it only after private endpoint, DNS, and workload connectivity are configured.
- Vault deletion can be blocked while protected items, registered storage accounts, or soft-deleted backup data remain. Follow Azure's recovery and deletion steps before destroying a vault.

## Identity and RBAC

The module does not create managed identities or role assignments. Assign backup operator, backup contributor, and restore permissions through separately managed RBAC according to operational separation-of-duties requirements.

## Naming and Tagging

Set `name` explicitly or allow `rsv-<workload>-<region-code>-<environment>-<instance>` generation. Vault names must be 2-50 characters, start with a letter, and contain only letters, numbers, and hyphens. Caller tags override inherited resource-group tags. See the repository [naming convention](../../docs/60-security-governance/naming-convention.md) and [tagging standard](../../docs/60-security-governance/tagging-standard.md).

## Known Limitations

- The module creates only the vault; backup policies and protected items are not managed here.
- It does not configure private endpoints, private DNS, diagnostic settings, alerts, or RBAC assignments.
- It cannot validate whether the selected redundancy, restore features, private networking, retention, or workload combination is supported for a particular region or data source.
- Locked immutability and backup data retention can prevent vault deletion. Review lifecycle and recovery requirements before applying destructive changes.
