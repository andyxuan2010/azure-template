# Azure SQL Managed Instance Database

Creates one database on an existing Azure SQL Managed Instance with optional diagnostics, resource-group tag inheritance, and control-plane RBAC on both the database and parent instance.

## Features

- Explicit database name or deterministic generated name
- Existing Managed Instance lookup by name and resource group
- Resource-group tag inheritance with caller overrides
- Optional diagnostics to Log Analytics
- Microsoft Entra group lookup by object ID or display name
- Database Contributor or Reader assignments plus parent-instance Reader assignments
- Outputs for the database, parent instance, FQDN, diagnostics, and RBAC resources

## Resources Created

The module always creates one `azurerm_mssql_managed_database`. It conditionally creates one diagnostic setting and up to four sets of role assignments for supplied admin and user groups.

It looks up but does not manage the existing Managed Instance, its resource group, or Microsoft Entra groups. It does not create SQL logins, contained users, database roles, schemas, backup policies, alerts, or failover configuration.

## Prerequisites and Dependencies

- Existing Azure SQL Managed Instance
- Existing resource group containing that instance
- Network and DNS access for database administrators and clients
- Existing Log Analytics workspace when diagnostics are enabled
- Directory read permission when group display names are used
- Exclusive Terraform ownership of the managed database and matching RBAC assignments

## Provider Configuration

The caller supplies `azurerm` and `azuread` provider configurations. The execution identity needs permission to read the Managed Instance, create managed databases, configure diagnostics, and create role assignments.

Prefer immutable Microsoft Entra object IDs to avoid ambiguous display-name lookup.

## Basic Usage

```hcl
module "orders_database" {
  source = "./modules/sqlmi_db"

  app_sqlmi    = module.sqlmi.name
  app_sqlmi_rg = module.sqlmi.resource_group_name
  name         = "orders"

  inherit_resource_group_tags = false
  tags = {
    Environment = "prod"
    ManagedBy   = "Terraform"
  }
}
```

See [examples/basic](./examples/basic), [examples/complete](./examples/complete), and [examples/generated-name](./examples/generated-name).

## Important Behavior and Secure Defaults

Diagnostics and RBAC are opt-in. Resource-group tag inheritance is enabled by default; caller tags override inherited values.

`name` is the preferred database-name input. `app_sqlmi_db` is a deprecated compatibility alias. When both are empty, the generated name is `sqmidb-<workload>-<environment>-<instance>`.

Deleting this module destroys the managed database unless lifecycle controls outside the module prevent it. Confirm backup, retention, restore, and data-loss procedures before destroy or replacement.

## Networking and Data-Plane Access

The database uses the parent Managed Instance network path. This module does not change the delegated subnet, public endpoint, DNS, NSGs, routes, peering, or private connectivity.

Azure RBAC assignments do not create SQL logins or database users. A separate database deployment process must configure contained users, roles, schemas, and permissions.

## Identity and RBAC

For every `app_admin_group` principal, the module creates database Contributor and parent Managed Instance Reader. For every `app_user_group` principal, it creates Reader at both scopes.

These roles manage Azure resources rather than Transact-SQL data access. Import pre-existing matching assignments before this state takes ownership.

## Naming and Tagging

Set `name` explicitly when application contracts depend on a stable database name. Generated names use the module's `sqmidb` prefix for backward compatibility. See the repository [naming convention](../../docs/NAMING_CONVENTION.md) and [tagging standard](../../docs/TAGGING_STANDARD.md).

## Testing

```powershell
terraform init -backend=false
terraform test -filter=tests/unit.tftest.hcl
```

The unit suite mocks AzureRM and AzureAD, including the parent instance and resource group lookups. It runs plan-only assertions, requires no cloud authentication, and creates no resources.

## Known Limitations

- One managed database is created per module instance.
- Parent instance settings, backup policy, failover, restore, alerts, and SQL permissions are not managed.
- Diagnostic categories are limited to the values accepted by the module.
- The legacy `name` output refers to the parent Managed Instance; use `managed_database_name` for the database.
- Azure validates database-name availability and parent-instance operational state during apply.

See [Architecture and Ownership](./docs/architecture.md).
