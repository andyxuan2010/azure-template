# Azure Private Endpoint

Creates one Azure Private Endpoint with an optional Private DNS zone group, static IP configurations, inherited tags, and shared-network lookup support.

## Features

- Direct subnet and Private DNS zone IDs
- Optional subnet and zone lookup by name through `azurerm.prod`
- Automatic or manual private service connection
- Multiple target subresource names
- Optional static IP configurations and custom NIC name
- Deterministic generated endpoint and service connection names
- Optional resource group tag inheritance

## Resources Created

The module creates one `azurerm_private_endpoint`, including its private service connection and optional nested DNS zone group and IP configurations.

It does not create the target service, subnet, Private DNS zones, VNet links, DNS Resolver resources, or approval automation.

## Prerequisites and Dependencies

- Existing resource group and Private Endpoint-capable subnet
- Existing target resource ID and correct service subresource name
- Existing Private DNS zones and VNet links when DNS integration is enabled
- Default `azurerm` provider for the endpoint subscription
- `azurerm.prod` provider for optional shared subnet and DNS lookups

## Provider Configuration

The alias must be passed even when direct IDs are used:

```hcl
provider "azurerm" {
  features {}
}

provider "azurerm" {
  alias = "prod"

  features {}
}

module "private_endpoint" {
  source = "./modules/private_endpoint"

  providers = {
    azurerm      = azurerm
    azurerm.prod = azurerm.prod
  }

  # Inputs...
}
```

## Basic Usage

```hcl
module "storage_blob_private_endpoint" {
  source = "./modules/private_endpoint"

  providers = {
    azurerm      = azurerm
    azurerm.prod = azurerm.prod
  }

  resource_group_name            = "rg-application-prod"
  location                       = "canadacentral"
  subnet_id                      = module.vnet.subnet_ids["private-endpoints"]
  private_connection_resource_id = module.storageaccount.id
  subresource_names              = ["blob"]
  private_dns_zone_ids = [
    module.private_dns.zone_ids["privatelink.blob.core.windows.net"]
  ]

  inherit_resource_group_tags = false
}
```

See [examples/basic](./examples/basic), [examples/complete](./examples/complete), and [examples/shared-network-lookups](./examples/shared-network-lookups).

## Direct IDs and Shared Lookups

Prefer direct IDs from upstream module outputs when resources are composed in the same Terraform state. When network and DNS resources live in a shared subscription, name-based subnet and zone lookups run through `azurerm.prod`.

The default provider always creates the Private Endpoint. The alias does not change the deployment subscription.

## Connection and DNS Behavior

Use one module instance per target resource and subresource group. Confirm the exact subresource name required by the target service, such as `blob`, `vault`, `sites`, `sqlServer`, or `namespace`.

Automatic connections are the default. Manual connections require approval by the target resource owner and can remain pending after apply. A DNS zone group associates existing zones; required VNet links and hybrid forwarding remain caller responsibilities.

## Static Addresses

Leave `ip_configurations` empty unless deterministic addresses are required and supported by the service. The requested address must be available in the endpoint subnet, and `member_name` requirements vary by target service.

## Testing

```powershell
terraform init -backend=false
terraform test -filter=tests/unit.tftest.hcl
```

Tests mock both provider configurations and perform plan-only validation.

## Known Limitations

- One Private Endpoint is created per module instance.
- Service-specific subresource and static-IP rules are not inferred.
- The module does not approve manual connections.
- DNS zones and VNet links must already exist.
- Azure validates subnet policy, target approval, service compatibility, and IP availability at apply time.

See [Architecture](./docs/architecture.md) and the repository [Private Endpoint and Private DNS Lookup Pattern](../../docs/PRIVATE_ENDPOINT_PRIVATE_DNS_LOOKUP_PATTERN.md).
