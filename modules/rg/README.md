# Azure Resource Group

Creates one Azure Resource Group with caller-controlled tags, optional generated naming, management lock, and resource group-scoped RBAC.

## Features

- Explicit or generated resource group name
- Deterministic instance suffix or optional random suffix
- Caller-owned tags without hidden module tags
- Optional `CanNotDelete` or `ReadOnly` management lock
- Contributor and Reader shortcuts for Entra groups
- Arbitrary resource group-scoped role assignments
- Optional `managed_by` and operation timeouts

## Resources Created

- One Azure Resource Group
- Optional management lock
- Optional RBAC assignments
- Optional random string used only for generated naming

## Prerequisites and Dependencies

- Subscription permissions to create resource groups
- Microsoft Entra read permission when resolving group display names
- RBAC permission, such as User Access Administrator, when assignments are requested
- An explicit naming, tagging, locking, and deletion policy

Resource groups are foundational dependencies and should normally be created before workload modules.

## Basic Usage

```hcl
module "resource_group" {
  source = "./modules/rg"

  name     = "rg-orders-cc-prod-001"
  location = "canadacentral"
  app_env  = "prod"

  tags = {
    Environment = "prod"
    Owner       = "orders-team"
    ManagedBy   = "Terraform"
  }
}
```

See [examples/basic](./examples/basic), [examples/complete](./examples/complete), and [examples/generated-name](./examples/generated-name).

## Naming and Tags

An explicit name is recommended for long-lived environments. When `name` is empty, the default random suffix is stored in Terraform state. Set `use_random_suffix = false` and provide stable naming inputs for deterministic generated names.

`app_env` participates in generated naming but does not add tags. The module applies exactly the caller-provided `tags`.

## Locks and Deletion

`CanNotDelete` prevents deletion while allowing updates. `ReadOnly` can block resource creation and updates inside the resource group and should be used only with a deliberate operating process. The module creates its lock after its RBAC assignments.

Destroying a locked resource group requires removing the lock first. Resources owned by other states can also prevent safe deletion.

## RBAC

Prefer object IDs over group display names. Display-name lookup supports Entra groups only and requires unique names.

Each custom role assignment must set exactly one role selector. Matching assignments outside Terraform state are not adopted; import them or assign a single owner before apply.

## Testing

```powershell
terraform init -backend=false
terraform test -filter=tests/unit.tftest.hcl
```

Tests use mocked providers and do not create subscriptions resources, locks, or RBAC.

## Known Limitations

- One resource group is created per module instance.
- The module does not enforce an enterprise tag schema.
- Group display-name lookup does not resolve users or service principals.
- Existing RBAC assignments and resource groups are not adopted automatically.
- Subscription-level policy, budgets, diagnostic settings, and resource deployment remain separate concerns.

See [Architecture](./docs/architecture.md) for lifecycle and ownership boundaries.
